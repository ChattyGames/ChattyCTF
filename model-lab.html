ChattyGPT / Real people. Real projects. Your voice.

Build a model. Prove it works.

For the students who want technical depth: real data, model choices, hardware specs, training, and reproducible testing—not just a chatbot wrapper.

Advanced path, not a prerequisite. You do not need to write code to complete ChattyGPT. If you want access to Moss’s classroom servers, plan your project now and request approval when Moss returns. Do not download models or run training on school hardware without permission.

Start by making one choice

PATH 1 / LOWEST FRICTION

Run an existing model

Pick a narrow task: classify text, answer questions, label photos, or summarize a short document. Try it, document five failures, and compare a second model.

You need: a model license, hardware check, test questions and a safety plan.

PATH 2 / BEGINNER TRAINING

Train a small model

Gather labeled examples (with permission), train a small image/audio classifier, measure accuracy and test cases it has not seen.

You need: labels, consent, split training/test sets, and a simple results table.

PATH 3 / MORE TECHNICAL

Customize an existing model

Use prompting, retrieval over approved documents, or—only if resources permit—fine-tuning. Explain which parts actually changed.

You need: a baseline, dataset quality checks, compute and a reproducible test.

PATH 4 / ENGINEER

Build an evaluation harness

Automate the same test cases across models or configurations, compare outputs, record failures, and make a model report card.

You need: test prompts, expected results, scoring rules and a run log.

Choose your specs before touching a server

Task & modelWhat should the model do? What is its size, license and origin?
HardwareWhat CPU, RAM, GPU/VRAM and storage are available? Unknown until Moss checks.
DataWhere did the examples come from? Do you have permission? No private student data.
HarnessWhat is success, what tests will run, how are errors counted?
ResourcesHow long might this run and what would it cost? Prefer a tiny proof of concept.
SafetyWho may use it? What happens with risky or wrong outputs?
